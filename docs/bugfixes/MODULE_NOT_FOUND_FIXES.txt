# Phân tích lỗi `ModuleNotFoundError` tiềm ẩn trong `app_gui.py`

Dưới đây là danh sách các vị trí có thể gây ra lỗi `ModuleNotFoundError` trong file `app_gui.py`, kèm nguyên nhân và hướng khắc phục. Chia thành 3 nhóm: **import nội bộ**, **import thư viện bên ngoài**, và **import có điều kiện**.

---

Những import này sẽ gây lỗi nếu file tương ứng không tồn tại trong hệ thống thư mục. Cần đảm bảo toàn bộ cấu trúc dự án được hoàn chỉnh.

## 2. Import thư viện bên ngoài (third-party)

Một số thư viện có thể chưa được cài đặt, nhưng đã được xử lý bằng `try/except` ngoại trừ `win32gui`.

### 2.1. Đã được bắt ngoại lệ
| **Thư viện** | **Dòng** | **Tác động** |
|--------------|----------|--------------|
| `pyautogui` | `try: import pyautogui` | Nếu thiếu, biến `pyautogui` được đặt là `None`, sau đó có kiểm tra trước khi dùng. |
| `PIL (Image, ImageDraw, ImageTk)` | `try: from PIL import ...` | Thiếu thì các biến gán `None`, không gây lỗi ở import. |
| `keyboard` | `try: import keyboard` | Thiếu thì biến `keyboard` là `None`, hotkey sẽ không hoạt động nhưng không crash. |
| `lib.system.screen_capture` | `try: from lib.system.screen_capture import ScreenCapture` | Nếu thiếu, `ScreenCapture = None`. |

### 2.2. Chưa được bắt (nguy cơ cao)
| **Thư viện** | **Vị trí** | **Nguy cơ** | **Cách xử lý** |
|--------------|------------|-------------|----------------|
| `win32gui` | Trong hàm `main()`: `import win32gui` | **Cao** – Nếu thiếu pywin32, chương trình sẽ crash ngay khi khởi động. | Thêm `try/except ImportError` và hiển thị thông báo lỗi thân thiện. |
| `ctypes.wintypes` | Đã import ở đầu file | `ctypes` là built-in, không có vấn đề. | - |
| `queue`, `threading`, `datetime`, ... | Built-in | Không gây lỗi. | - |

## 3. Import có điều kiện (được import bên trong hàm/phương thức)

Những import này chỉ được gọi khi chạy đến dòng đó, vì vậy lỗi có thể xuất hiện muộn.

| **Module** | **Vị trí** | **Nguy cơ** | **Ghi chú** |
|------------|------------|-------------|-------------|
| `ui.components` (import động trong `_create_icon_btn_component`) | `_build_ui` (khi tạo icon button) | Trung bình | Đã có `try/except`, nên không crash. |
| `ui.helpers.capture_helper` | `try: from ui.helpers.capture_helper import capture_region_and_save` | Trung bình | Đã bắt, gán `None`. |
| `lib.features.hunt.scan_controller` | `__init__` (dùng trong `ScanController` constructor) | Cao | Nếu file scan_controller không tồn tại, lỗi ngay khi khởi tạo. |

## 4. Đề xuất sửa chữa tổng thể

### 4.1. Đảm bảo cấu trúc thư mục
- Kiểm tra tất cả các file nội bộ được liệt kê ở Mục 1. Nếu thiếu, tạo file hoặc điều chỉnh import cho đúng.
- Sử dụng công cụ như `pylint` hoặc `mypy` để phát hiện import lỗi trong quá trình phát triển.

### 4.2. Xử lý thư viện ngoài
- Bổ sung `try/except ImportError` cho `win32gui` trong `main()`:
  ```python
  try:
      import win32gui
  except ImportError:
      print("⚠️ pywin32 chưa được cài đặt. Vui lòng chạy: pip install pywin32")
      sys.exit(1)
  ```
- Đối với các thư viện khác (PIL, keyboard, pyautogui), có thể hiển thị cảnh báo khi thiếu nhưng vẫn cho ứng dụng chạy với chức năng bị hạn chế.

### 4.3. Kiểm tra sự tồn tại của module database
- Import `database` ở dòng `from database import ...` có thể gây lỗi nếu file `database.py` không nằm ở thư mục gốc. Có thể thay bằng đường dẫn tương đối hoặc đảm bảo file tồn tại.

### 4.4. Sử dụng import absolute thay vì relative
- Nhiều import bắt đầu bằng `from lib...` hoặc `from ui...` đều là absolute (với điều kiện thư mục gốc nằm trong `sys.path`). Đảm bảo thêm đoạn `sys.path.insert(0, str(Path(__file__).parent.parent))` để thêm thư mục cha vào path. Đoạn này đã có trong file (dòng 68-69) nên các import nội bộ sẽ hoạt động nếu cấu trúc đúng.

### 4.5. Tạo file `__init__.py` trong các thư mục con
- Đảm bảo tất cả thư mục chứa module đều có `__init__.py` (có thể rỗng) để Python nhận diện là package.

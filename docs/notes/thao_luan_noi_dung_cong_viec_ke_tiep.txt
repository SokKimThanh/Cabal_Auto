Tổng quan dự án và ngữ cảnh
Dự án: Cabal_Auto, Sprint 22, repo chính trên GitHub.

Mục tiêu chính: tự động hóa hành vi trong game bằng hệ thống Vision, Skill Runtime, InputAdapter và UI quản lý.

Thành phần chính đã có: template matching (OpenCV/PyAutoGUI), skill runtime, library manager, setup wizard, hotkey settings, hunt logger, capture helper, UI đa thành phần.

Tình trạng hiện tại và vấn đề chính
Màn hình nhập thông tin quái vật bị xóa; chức năng nhập/quản lý quái vật bị gom chung vào Library Manager gây cồng kềnh và làm chậm thao tác cho người dùng, trong khi Library Manager là luồng xử lý cho skill rotation.

Cần tách rõ hai vai trò: Library Manager giữ chức năng Skill Rotation; Monster Editor là module độc lập cho CRUD quái vật, capture template và test recognition.

UI hiện có rủi ro block khi thực thi các tác vụ nặng như capture, template matching, I/O, hoặc gửi input.

Yêu cầu cho Monster Editor và cách báo cho Claude thực hiện
Tách module Monster Editor riêng, gồm: Library Overview, Quick Monster Editor (modal, hotkey), Full Monster Editor, Template Capture/Test panel.

Yêu cầu i18n và tooltip: mọi label và tooltip UI mới phải sử dụng lib/i18n và lib.ui.tooltip, có bản EN/VI mẫu.

Hotkey: Ctrl+Shift+M để mở Quick Editor, đăng ký qua HotkeyManager/ui/hotkey_settings.py, expose capability_report.

Threading: mọi tác vụ nặng phải chạy background (worker queue / signals), UI chỉ cập nhật qua signal/queue, có spinner, cancel, timeout.

Logging: emit sự kiện có cấu trúc vào hunt_structured.jsonl: monster_created, template_saved, template_test, hotkey_registered, task_started, task_done, task_cancelled.

Chiến lược test, CI và dependency
Test types: unit tests cho CRUD, HotkeyManager, InputAdapter; integration tests Vision→Skill→Input (mock InputAdapter); manual demos cho vision accuracy và hunt loop.

CI: mock InputAdapter để tránh gửi phím thật; Windows-only Interception tests chạy trên runner thích hợp với marker.

Dev dependencies cần thêm: pytest, pytest-mock, coverage, flake8; runtime extras tùy OS: interception-python/pywin32, python-evdev, pyobjc, mss.

Thiết lập requirements phân tầng: requirements.txt, requirements-win.txt, requirements-dev.txt..

Logging, quy tắc xử lý file log và bảo mật repo
Hai lớp log: human-readable logs (logs/hunt.log) và structured JSONL (logs/hunt_structured.jsonl) với schema chuẩn (timestamp, event, level, source, session_id, payload).

Logger phải dùng queue-based background writer, thread-safe, expose API như get_hunt_logger().log(...) và set_log_dir().

Quy tắc repo: không commit file log, thêm .gitignore cho logs, docs/logging.md giải thích LOG_DIR env và CI behavior.

Trong CI và tests, logs phải viết vào tmp_path hoặc RUNNER_TEMP; tests dùng fixture để mock LOG_DIR.

Diagnostics UI đọc recent events từ memory cache hoặc active log dir, không đọc files trong repo; Export lưu file vào đường dẫn do user chỉ định, không commit.

Tổng quan dự án và bối cảnh
Repo: https://github.com/SokKimThanh/Cabal_Auto; Sprint 22.

Mục tiêu chính: tự động hóa hành vi trong game bằng Vision, Skill Runtime, InputAdapter và UI quản lý.

Thành phần hiện có: Library Manager (hiện đảm nhiệm skill rotation), template matcher (OpenCV/PyAutoGUI), capture helper, hunt_logger, hotkey settings, skill runtime, đa module UI.

Vấn đề chính đã thảo luận
Library Manager đang bị dùng làm màn hình nhập quái vật dẫn tới cồng kềnh; cần tách Monster Editor độc lập và chỉ liên kết khi cần.

UI hiện có nguy cơ bị block khi thực thi tác vụ nặng: capture, template matching, file I/O, gửi input.

Thiếu quy tắc quản lý nhánh, commit, PR và skeletons cho feature mới.

Thiếu yêu cầu rõ ràng về i18n, tooltip và global hotkeys trong prompt gửi cho Claude.

Logging runtime phải được thiết kế cẩn thận để tránh commit file log vào repo và để tương thích CI.

Yêu cầu chức năng và ràng buộc kỹ thuật
Tách Module Monster Editor với Quick Editor modal, Full Editor, Template Capture/Test panel; Library Manager giữ skill rotation.

I18n bắt buộc cho UI mới bằng lib.i18n; tooltip phải dùng lib.ui.tooltip; cung cấp ví dụ key EN/VI.

Hotkey Ctrl+Shift+M đăng ký qua lib/hotkey/hotkey_manager.py hoặc ui/hotkey_settings.py; expose capability_report.

Tất cả tác vụ nặng phải chạy nền qua hàng đợi/worker; UI chỉ cập nhật qua queue/signal; hỗ trợ cancel và timeout; không cập nhật widget từ worker thread.

InputAdapter phải là hàng đợi non-blocking; trong CI phải mock để tránh gửi phím thật.

Logger tập trung dual output: human-readable logs và structured JSONL; schema chuẩn gồm timestamp, event, level, source, session_id, payload.

Không commit log runtime; dùng LOG_DIR env hoặc tmp_path; .gitignore bổ sung logs/, *.log, *.jsonl.

APIs, event list và test yêu cầu
Monster manager API: list_monsters, get_monster, create_monster, update_monster, delete_monster, add_template, test_template.

Worker API: start_worker, enqueue.

Hotkey API: register_hotkey, capability_report.

InputAdapter API: enqueue_send_key returning task_id.

Logger API: get_hunt_logger, set_log_dir, log(event, level, source, payload), log_task_start/done/cancel.

Events must emit: monster_created, monster_updated, template_saved, template_test, hotkey_registered, task_started, task_done, task_cancelled.

Tests: unit skeletons for CRUD, i18n keys, hotkey registration; integration mock test for Capture→add_template→test_template; tests must use tmp_path or monkeypatch to avoid writing repo logs.

Lưu ý kỹ thuật, an toàn và bước tiếp theo ngắn
UI threading patterns: Tkinter → worker+queue + after() polling; PyQt → QThread/QRunnable + signals.

Tránh ProcessPoolExecutor với đối tượng non-picklable; truyền file paths thay vì cv2.Mat.

Logger phải chạy trên background writer thread, ghi đồng thời text + JSONL, duy trì in-memory recent-events cache cho Diagnostics UI.

CI behavior: set LOG_DIR to runner temp, upload logs as artifacts, do not commit; add docs/logging.md và .gitignore entries.
